1. General Information

This Privacy Policy describes how personal data is processed by the Trip Asystent mobile application (the "Application").

The Application is a travel organizer designed to let users store, manage and organize information they provide themselves.

The Application does not require users to create an account, log in or register with a developer-operated server. The developer does not operate its own server for storing users' travel data and does not provide automatic synchronization of such data between devices.

Most Application data is stored locally on the user's device.

2. Data the Application May Process

The scope of data depends on the features used and the information the user chooses to provide.

The Application may store locally, among other things:

  • Trips, trip names, dates and itineraries;
  • Activities, attractions, accommodation, tickets and reservations;
  • Expenses, budgets and currency information;
  • Notes, travel journals, saved phrases and cultural information;
  • Packing lists and equipment information;
  • Documents, document numbers, photographs, files and other attachments added by the user;
  • Saved locations, coordinates and map data;
  • Emergency contacts, telephone numbers and messaging identifiers, such as Discord IDs and usernames;
  • SIM card, mobile operator and network information used by connectivity monitoring and related features;
  • Application settings, user preferences and security-related information.

Users decide what information they enter into the Application. Some of this information may be personal or sensitive, including document numbers, contact details, messaging identifiers, photographs of documents and private notes.

The developer has no access to the information stored by the Application on the user's device. The Application does not transmit this information to the developer or to any server operated by the developer.

3. Local Data Storage

Application data is primarily stored in the Application's private storage area on the user's device, using a local database, files and application preferences.

The Application does not automatically send the complete contents of users' trips to a developer-operated server and does not synchronize them with other devices.

Data remains on the user's device. The Application does not provide the developer with any mechanism for remotely accessing, viewing or retrieving this data. Certain Application features may, however, use external Internet or system services. In such cases, only the information necessary to fulfil the specific request is transmitted to the relevant service providers, as described in this Privacy Policy.

Application Password Protection

The Application allows users to set a password to lock the Application or selected modules.

The password is not stored in plain text. Password verification uses PBKDF2-HMAC-SHA256 with a unique, randomly generated salt.

The password hash, salt and verification parameters are stored locally in the Application's private storage.

The password, its hash, salt and verification parameters are excluded from JSON exports and Android backups.

This protection does not mean that all data stored by the Application is encrypted. The security of locally stored data also depends on the security of the device, the Android operating system and access to the device.

4. Location and Geocoding

The Application may use device location information for maps, compass features, location recognition and saving places.

Depending on the feature being used and the permissions granted, it may use the device's location or coordinates entered by the user.

The Application may store coordinates and location history locally on the device.

To convert coordinates into a place name, address or other textual information, the Application may use the Android system geocoding service. The service provider may be Google or another provider depending on the device.

In such cases, coordinates and information necessary to perform the request may be transmitted to the geocoding provider. The provider's processing of this information is subject to its own privacy policies.

The Application does not use background location permission and does not continuously track the user's location after the trip screen has been closed. Certain features may periodically refresh location while the relevant screen is active.

Location Sharing

Users may choose to share their location or emergency information, for example with SOS contacts.

The Application prepares the relevant content and passes it to an application or Android system feature selected by the user, such as SMS or a messaging application.

The recipient and subsequent processing of the information depend on the user's choice and the selected external application.

The Application does not automatically send emergency messages or locations to SOS contacts without user action.

5. Microphone and Voice Recordings

The Application may use the microphone to record voice notes.

Recordings are stored locally on the user's device, for example in M4A audio format.

The Application does not automatically upload recordings to a developer-operated server and does not use automatic speech-to-text transcription of recordings.

Users may choose to share recordings through Android system features or other applications.

6. External Services and Internet Connections

Some Application features require an Internet connection and may use external services.

6.1. Exchange Rates

The Application may retrieve exchange rates from open.er-api.com.

Currency codes and other information necessary to retrieve exchange rates may be included in requests.

The service provider may also receive standard technical connection information, including the device's IP address.

6.2. YouTube Playlist Import

The Application allows users to import or refresh YouTube playlists at their request.

For this purpose, it uses the YouTube Data API provided by Google.

Depending on the operation, the following information may be transmitted to Google:

  • Playlist identifier;
  • API key used to perform the request;
  • Standard technical connection information, including the IP address and application-identifying headers.

Requests are made in connection with the user's use of the playlist import or refresh feature.

6.3. Google Fonts

The Application may use Google Fonts in its print preview feature. Fonts may be retrieved from:

  • fonts.googleapis.com
  • fonts.gstatic.com

The provider may receive standard technical information, including the IP address, when these resources are requested.

6.4. External Images

The Application may display images from external Internet addresses supplied or used by the user.

In such cases, image requests are sent to the server hosting the relevant resource. That server may receive the IP address and standard technical connection information.

6.5. Online Maps and Embedded WebView

The Application allows users to open online maps, including Google My Maps, in an embedded WebView within the Application.

This view may use cookies, including third-party cookies, local browser storage (DOM storage) and browser cache to display and operate the external map service.

These technologies may allow the provider of the displayed map or website to store or access information in accordance with its own settings and privacy policy. The provider may also receive standard technical connection information, such as the device's IP address.

The processing of data by the external map or website provider is governed by that provider's own terms and privacy policy.

6.6. Android System Services

The Application may use Android system services and Google services available on the device, such as geocoding, location features, sharing mechanisms and system backups.

Data processing by these providers is subject to their own policies and the user's device settings.

The Application does not use Firebase AI Logic or Firebase App Check. These dependencies have been removed from the project.

7. Data Export and Sharing

The Application allows users to export or prepare data in several formats, including:

  • A full Application data export in JSON format;
  • An individual trip export in JSON format;
  • A Draft export in JSON format;
  • TXT files used for data transfer and editing on a computer, including importing edited files back into the Application;
  • PDF files and print-ready documents generated by the Application.

Export files may contain many types of information provided by the user, including notes, documents, attachments, contact information, trip information and other saved content.

Before a full export, an individual trip export or a Draft export, the Application displays a warning informing the user that data and files will be consolidated into a single file.

The export proceeds only after the user confirms.

The Application password, its hash, salt and verification parameters, as well as API keys stored in the secrets storage, are not included in JSON exports.

After a file is created, the user decides where to save it and whether to share it with other people or applications.

The developer does not receive exported files or copies of them. Exported files remain under the user's control, and the user decides where to save them and whether to share them.

Export files may contain personal data and other private information. Users should store them securely and share them only with trusted recipients.

8. Android Backups

The Application uses Android backup mechanisms, depending on the Android version, device configuration and user account settings.

Backups may include trip data, the local database, files and certain Application settings.

The Application password, its hash, salt, verification parameters and the file containing secrets are excluded from Android backups, including cloud backups and device-to-device transfers.

Backups are handled by Android system mechanisms and may be stored by Google services according to the user's device and account settings. The Application developer has no access to the contents of these backups.

9. Technical Data and Permissions

Depending on the features used, the Application may use Android permissions relating to:

  • Internet access and network status;
  • Location;
  • Microphone;
  • Notifications;
  • Access to selected SIM card and mobile operator information;
  • Access to local audio files;
  • Background media playback;
  • Biometric security.

Certain technical information, such as network status, operator, SIM data or battery level, may be used by Application features, including connectivity monitoring and emergency features.

The scope of permission use depends on the features activated by the user and the permissions granted through Android.

10. Advertising, Analytics and Tracking

The Application does not contain its own advertising modules or analytics modules designed to profile users.

The Application does not use Firebase Analytics or Firebase Crashlytics.

It does not automatically track user activity for behavioural advertising purposes.

However, external Internet or system service providers may process standard technical information associated with connections.

11. Data Deletion

Users can delete individual records and trips using the features available in the Application.

The Application also provides mechanisms for permanently deleting selected data.

However, not all associated files are automatically deleted together with the records to which they are attached. This may apply in particular to certain audio files, photographs and images stored in the Application's storage. Some settings associated with a trip may also require separate deletion.

The Application does not provide a single universal function that guarantees deletion of all data and files in one action.

To remove all locally stored Application data, users may clear the Application's data through Android settings or uninstall the Application.

Uninstalling the Application or clearing its local data does not automatically delete export files stored outside its private storage or backups retained by Android. Users must delete these separately if they also wish to remove those copies.

12. Data Security

The developer uses measures intended to reduce the risk of unauthorized access to data, including:

  • Storing data in the Application's private storage area;
  • Separating secrets from ordinary settings;
  • Excluding secrets from exports and backups;
  • Cryptographic protection of Application password verification;
  • Using Android permission mechanisms.

Requests made by the Application to its integrated external services, such as the exchange-rate service, YouTube Data API and Google Fonts, use HTTPS connections protected by TLS.

However, the Application may also open external websites, maps or image addresses supplied by the user. Depending on the address and the external server, these resources may use HTTPS or unencrypted HTTP. The Application cannot guarantee the security of connections or content provided by external websites and services.

Data stored locally in the Application's database, files and preferences is not individually encrypted by the Application. Its protection depends in part on Android's private application storage, the device's security and the operating system.

No method of data storage or transmission can guarantee absolute security.

Users should protect their devices against unauthorized access, use available system security features and exercise caution when sharing exported files or opening external links.

13. Children's Privacy

The Application is not specifically directed at children and does not knowingly collect children's data through a developer-operated server.

This Privacy Policy may be updated if Application features, data processing practices or legal requirements change.

The current version of this document will be available at the public Internet address provided in Google Play.
